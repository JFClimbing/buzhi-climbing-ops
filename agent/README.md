# 新媒体每日数据自动化 Agent（抖音 + 小红书 → 飞书多维表格）

> 给「不止攀岩攀岩工作室」用。每天定时把抖音、小红书两个账号的内容数据整理成
> 「素材明细 + 每日汇总 + 日报小结」，写进飞书多维表格里**独立的一张表**，
> 不动排班表、装备出入库表。

---

## 0. 先说清楚合规边界（重要）

| 你要求 | 现实 | 本方案怎么做 |
|---|---|---|
| 优先平台官方开放 API | 抖音开放平台、小红书开放平台**都有内容数据接口，但要企业/专业号资质 + 应用审核 + 权限包**，个人号通常拿不到「粉丝增量、私信咨询」这类字段 | 代码里留了**官方 API 适配层**（`sources/api_*.py` 骨架 + 申请清单），拿到权限后填 app_id/secret 即可切换；在那之前走下面这条合规链路 |
| 禁止爬虫、违规抓包 | 完全同意 | **不写任何爬虫**。数据来自两个官方后台自带的「导出」功能（平台自己提供的下载），脚本只解析导出文件 |
| 私信咨询数、咨询来源、报名意向 | 官方 API 基本不提供；私信数据在专业号/企业号客服后台 | 设计成**人工补录列**（前台每天填 1 个数），或在飞书里用表单补录；日报里会标注「人工项」 |

所以默认链路是：**官方后台导出（平台允许）→ 本脚本解析 → 飞书多维表格 API 写入 → 自动生成日报小结**。
这条路今天就能跑、零违规风险；等官方 API 权限下来再切 API 模式，其余部分不用改。

## 1. 整体架构

```
┌─────────────── 每天 23:10（Windows 任务计划） ───────────────┐
│                                                              │
│  ① 采集层 sources/                                            │
│     collect_douyin.py  ← data/inbox/douyin_export_*.csv      │
│     collect_xhs.py     ← data/inbox/xhs_export_*.csv         │
│     （可选）api_douyin.py / api_xhs.py  ← 官方开放平台         │
│                                                              │
│  ② 标准化层  → 统一的「素材记录」结构（见 字段映射说明.md）      │
│                                                              │
│  ③ 汇总层    → 每日汇总行（总曝光/总互动/新增粉丝/咨询量）        │
│                                                              │
│  ④ 小结层    → 规则模板生成「每日小结」（可选接 LLM 润色）        │
│                                                              │
│  ⑤ 写入层 feishu.py → 飞书多维表格 素材明细表 + 每日汇总表       │
│     失败 → 写「异常状态/失败原因」列，不影响其他表                │
└──────────────────────────────────────────────────────────────┘

飞书 Base（同一个工作台）
 ├─ 排班表            （已有，本脚本只读不写）
 ├─ 装备出入库台账     （已有，本脚本只读不写）
 └─ 新媒体每日数据汇总表（本脚本新建/写入，独立表，不会冲突）
      ├─ 视图 1：素材明细（一条素材一行）
      └─ 视图 2：每日汇总（一天一行）
```

**为什么新建两张表**：你说「单条素材一条记录」+「另外单独一条每日汇总行」。飞书多维表格里混在一张表也能做（用「类型」字段区分），但汇总行的列和素材行对不上、视图会很难看。建议**同一张表两个视图**或**两张表**——本方案默认**两张表**：
- `新媒体-素材明细`
- `新媒体-每日汇总`

（也在同一张表里用 `记录类型` 字段区分，代码里一个开关 `SINGLE_TABLE=true` 即可切）

## 2. 三步上线

### 第 1 步：建飞书自建应用（一次性，5 分钟）
1. 打开 https://open.feishu.cn/app → 「创建企业自建应用」，名字填「攀岩工作室数据助手」
2. 「权限管理」里加：
   - `bitable:app`（多维表格读写）
   - `drive:drive`（上传封面附件，可选）
3. 「版本管理与发布」→ 创建版本并发布（企业内应用一般即时生效）
4. 把 `app_id`、`app_secret` 填进 `config.json`

### 第 2 步：建多维表格 & 给应用授权
1. 在工作台 Base 里新建两张表（字段照 `字段配置清单.md` 建）
2. 表格右上角「…」→「添加文档应用」→ 选「攀岩工作室数据助手」，给**可编辑**
3. 从浏览器地址栏拿 `app_token`（`/base/` 后面那串）和每张表的 `table_id`（`?table=` 后面），填进 `config.json`

### 第 3 步：每天导出 + 定时跑
- 每天手动（或让前台）在各平台后台点「导出」，把文件丢进 `data/inbox/`
- 定时任务每天 23:10 跑 `daily_job.py`（见 `定时任务说明.md`）
- 想全自动导出：抖音创作者中心/小红书的「数据导出」是网页按钮，**不要**用脚本模拟点击（那算爬虫）；用手机 App 的定时提醒人工点一下最稳，或者等官方 API 权限

## 4. 异常处理约定

每次运行结果写一行「运行日志」到汇总表旁边的 `异常状态` 列：

| 情况 | 标记 | 后续 |
|---|---|---|
| 某平台导出文件缺失 | `异常：抖音无导出文件` | 该平台当天数据留空，另一平台照常写 |
| 导出文件解析失败 | `异常：解析失败(原因)` | 原始文件保留在 `data/failed/`，人工看 |
| 飞书接口 401 | `异常：飞书鉴权失败` | 不发写入，本地 JSON 落盘，重试 3 次 |
| 飞书限流 429 | 自动退避重试（1/2/4 秒） | 最多 3 次，仍失败写异常 |
| 当天确实没发内容 | `正常：无新素材` | 汇总行仍写（全 0），日报小结说明「今天没发」 |

**不影响其他表**：本脚本只带 `新媒体-*` 两张表的 table_id，碰不到排班和装备表。

## 5. 日报小结长什么样（示例）

> 今日发布 1 条素材（抖音 1、小红书 0）。表现最好的是《辅助管式保护器 到底好不好用？》，
> 播放 19,300、赞 96、藏 14，播放/赞比约 201:1。两平台合计曝光 19,334、互动 121、新增粉丝 6。
> 咨询线索：小红书私信 3 条（人工补录），报名意向 1 人。
> 建议：这条「装备横评 + 结论前置」的结构可复制，下一条优先做「快挂怎么选」同题材；
> 评论区 7 条里 2 条在问「新手要不要买」，可在下条视频结尾挂体验课报名引导，并把
> 「体验课 3 小时 ¥368」放进置顶评论。

## 🚀 三步上线

```powershell
# 第 1 步：配凭证
copy config.example.json config.json
notepad config.json      # 填 feishu.app_id / app_secret / app_token

# 第 2 步：在飞书建表建字段（幂等，跑几次都没事）
python setup_tables.py --yes
# 把打印出来的 table_id 填回 config.json 的 table_material / table_daily

# 第 3 步：先演练，再真跑
python make_sample_exports.py
python daily_job.py --dry-run --date 2026-09-30
python daily_job.py --date 2026-09-30
```

第 3 步的 dry-run 只把要写的内容落盘到 `dryrun/`，不碰飞书 —— 先看一眼字段对不对，再真跑。

## ✅ 已经验过的

- `python daily_job.py --dry-run --date 2026-09-30` → 抖音 1 条 + 小红书 1 条 → 素材 2 条 + 汇总 1 行（曝光 2,191 / 互动 127 / 新增粉丝 43），运行状态=正常
- 生成的每日小结（真实输出）：
  > 今日发布 2 条素材（抖音 1、小红书 1）。表现最好的是《攀岩主锁的型or形？一篇视频讲清楚》，曝光 2,145、赞 79、藏 19。两平台合计曝光 2,191、互动 127、新增粉丝 43。咨询线索：今天还没填（私信数/报名意向需人工补录）。建议：抖音曝光远高于小红书，小红书那条可换更吸引人的首图再发一次。
